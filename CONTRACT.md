# Advanced Bank Search contract

This describes what Advanced Bank Search uses from Bank Core, Bank Tags, RuneQL, GE Prices, and the host. It offers no API of its own. Like Bank Core's API it has no version number: nothing has shipped, so a change updates this document and the tests.

## Plugin identity

- Plugin name `advancedbanksearch`. PrettyUI is required; `bankcore`, `runeql`, `geprices`, and `banktags` are optional dependencies.
- The entry returns nothing. The running session is `_G.__advancedbanksearch_session`; a new load shuts it down first.
- Event names start with `advancedbanksearch_`: `advancedbanksearch_price_wait` (subscribed only while a price wait runs), `advancedbanksearch_search_wait` (while typed text waits to search), `advancedbanksearch_menu` (`MiniMenuReady`, while connected to Bank Core), and `advancedbanksearch_menu_action` (a chosen menu entry, until the next logic tick).
- Saved data: `advancedbanksearch:queries:v1:manifest` and `advancedbanksearch:queries:v1:<a|b>:<n>` chunks of JSON `{ schemaVersion = 1, nextId, queries = { { id, name, query, builder? } }, nextFolderId, folders = { { id, name, collapsed, queries = { queryID, ... } } }, order = { { kind = "query" | "folder", id } } }`. `order` is the top level: folders and the queries in no folder; a folder's `queries` are its members in order. A save without `folders` and `order`, as earlier builds wrote, loads with every query ungrouped in `queries` order. On load a query listed by two folders stays in the first, IDs that name nothing and folders without a valid ID or name are dropped (their queries kept), and anything `order` misses goes at its end. Query and folder IDs never change and are never reused. Nothing else is read or written.
- `builder` is optional: the visual conditions a query was built from, `{ match = "all" | "any", rules = { { field, operator, value?, min?, max? } } }` with 1 to 6 rules. `field` is `name` (`operator` `phrase` or `words`, `value` text) or `qty`, `price`, `gehigh`, or `gelow` (`operator` `equals`, `atleast`, or `atmost` with an integer `value`, or `between` with integer `min` and `max`). `query` stays what is searched. A `builder` is kept on load and save only when it is valid and builds exactly `query`; otherwise it is dropped and the query kept. A record without one loads and saves unchanged.

## What it uses from Bank Core

Only the launch API in Bank Core's `docs/LAUNCH_API_SPEC.md`:

- `Register{ id = "advancedbanksearch", name = "Advanced Bank Search", icon = "SEARCH", column, onClose, onBankItems, onBankClose }` on the injected `bankcore` or `__bankcore_api`, when the plugin starts and whenever the host reports `bankcore` enabled; `Dispose` when it is reported disabled and when the plugin stops. Registering again replaces the earlier registration.
- The column (`mount`, `resize`, `unmount`) is the plugin's own: a PrettyUI text field, sort button, status text, list, and buttons, built in `ctx.parent` at `ctx.width` by `ctx.height`, with tooltips in `ctx.overlay`. `resize` with the same width moves the footer and list in place, so the field keeps its focus and typed text; a new width builds the column again. No drops, settings section, launchers, or highlights.
- Menus over the column's rows are the plugin's own, from its `MiniMenuReady` handler: a menu `GetMenuItem` describes is a bank item's and is left alone; otherwise the row under the pointer is found from `ctx.parent`'s position, `ctx.width` and `ctx.height`, and the list's scroll. Entries are added at the lowest priority, found by comparing the menu before and after, so the default and a promoted Cancel stay the left click. A chosen entry runs on the next logic tick, only while the extension and mounted column are the same and the row's query or folder still exists, both when chosen and when it runs.
- The free search page is `{ title = "Search", rows = { { slots = ranked } } }`; a saved query's is `{ title = <name>, rows = ... }`. `ranked` lists each matching stack's object ID in rank order, so an object appears once per matching stack and Bank Core shows its stocked stacks first, then placeholders. A page with no stacks is one label row: "No items match", "RuneQL could not read this search", "This search needs GE Prices", "Waiting for GE prices...", "GE prices did not load", "This search needs RuneQL", or "The bank's items are not available yet".
- Searching or choosing a query calls `SetPage`, then `Open`, which starts at the top. A refusal from `Open` is said in the column's status line (`not_all_items` and `preset_open` say what to do). Choosing the shown query again, clearing the text, deleting the shown query, or RuneQL unloading calls `Close`. Which page shows is the plugin's record of the last page it set plus `IsOpen()`.
- `onBankItems`, a price arrival, and a GE Prices change rank the last page set again and give it to `SetPage`: Bank Core redraws it in place while it shows and otherwise only keeps it, so a late result never takes the bank from another plugin or the native view. Saving the shown query does the same. Only a shown page updates the status line or starts a price wait.
- `onClose` ends a price wait and refreshes the column. `onBankClose` drops the last bank read and typed text waiting to search, and closes the editor and folder dialog.
- `GetBankItems` gives `{ objectID, quantity }` per stack; the last read is kept while it answers `busy` or `not_all_items`. `quantity == 0` is a placeholder, left out of saved-query pages.

## Ranking

- RuneQL's `Compile(text)` gives a plan, or nil and a reason. Each stack is scored with `plan:Score({ name, configName, quantity, fields })`, the name from `config.Obj.FromID(id).name` and the config name from its `configName`. Matches are sorted by score, descending, ties in View All order.
- When `plan:Requirements()` names `price`, `gehigh`, or `gelow`, the plan is ranked only once GE Prices' `isReady()` is true, with `fields.gehigh`, `fields.gelow`, and `fields.price` from `getPrice(id)` (positive numbers only; an error is no price). RuneQL lets a negated range match a row without the field, so ranking before prices load would be wrong.
- RuneQL is read from the injected `runeql` or `__runeql_api`, and GE Prices from `geprices` or `__geprices_api`, only while the host last reported them loaded.

## Visual queries

The editor builds RuneQL text from conditions and saves it through the same `Compile` check as typed text; RuneQL never reads the conditions. A condition becomes one clause: `name:"text"` for a phrase, `(name:"a" AND name:"b")` for all of several words, and `field:[low TO high]` for numbers, with `*` for an open end and both ends included. Clauses are joined with ` AND ` or ` OR `, never mixed, so Lucene's mixed-operator rules never apply. Inside the quotes, `\` and `"` are escaped with `\`; everything else is literal phrase text, which RuneQL splits into lowercase letter-and-digit words. Text with no letter or digit, which RuneQL could never match, is refused. Number conditions are ranges, which match no row missing the field, and they need prices as any other price query does.

## What it uses from Bank Tags

Only the import-source API in Bank Tags' `CONTRACT.md`:

- `RegisterExtension("advancedbanksearch", "Advanced Bank Search")` on the injected `banktags` or `__banktags_api`, and one provider `saved-search`: label "Saved bank search", icon `SEARCH`, `input = "text"`, a prompt and placeholder, and `unavailable` while Bank Core is not registered or RuneQL is not loaded (updated with `UpdateImportProvider` when that changes). The handle is disposed when Bank Tags is reported unloaded or this plugin stops; a handle a newer copy replaced is never registered again.
- A request's input names a saved search. The answer is `Resolve({ tags = { { name = <query name without commas>, rows = { { objectID, ... } } } } })`, one entry per matched stack in rank order, placeholders left out, so an object matched in k stacks appears k times, whichever of its stacks Bank Tags then shows. For more than 1,999 stacks, no matches, a closed bank, another tab than All Items, a busy bank, an unreadable query, missing or loading prices, or an unknown name, the answer is `Fail` with a reason under 120 characters. Answers are given while the request runs; no cancel function is returned.

## Host behavior it relies on

Checked with Bank Core's stand-in host only: `PluginDependencyUpdate` for all four optional dependencies; `PersistentDB:GetString` and `SetString` per plugin; PrettyUI's `TextField` (with `SetDisabled` and `SetPlaceholder`), `ComboBox` (`SetEntries`, `Select`, `GetSelectedID`, with whole-number entry IDs and an `order` on every entry, so PrettyUI builds its ordered combo box), `Text`, `List` (with `_onEntryClick`, `rows`, and `scrollY`), `SpriteButton` (`ARROW_UP`, `ARROW_DOWN`), `Sprites.SPRITE_BUTTONS.SWAP`, `Tooltip` (`bind`, `set`, `unbind`, `registerContext`, `unregisterContext`), a `ui.Button` in the `BUTTON_PANEL` style (318 when `id.StyleSheet` does not name it) answering `ONBUTTONPRESSED`, with a `ui.Sprite` icon beside it, `SimpleButton` (with `SetDisabled` and `SetActive`), and `Window`; `ui.Rectangle` and a rotated `ui.Sprite` (`id.Sprite.BANK_ARROW_UP_0`) in list rows; `ui.Interfaces:GetComponent(id.Component.TOPLEVEL_V2__BANK_LAYER)` for the editor's and folder dialog's parent; `Mouse.GetPosition` and `game.options.InterfaceScale`; `MiniMenu` `entries`, `entryCount`, `Add`, and `Swap`, and `MiniMenuActionType.CANCEL`; `Event.Logic` and `Event.MiniMenuReady`. The manifest sets `hasRibbonIcon` to `false`, and the plugin does not subscribe to `Event.ContentLayerReady`.
