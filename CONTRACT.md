# Advanced Bank Search contract

This describes what Advanced Bank Search uses from Bank Core, RuneQL, GE Prices, and the host. It offers no API of its own. Like Bank Core's API it has no version number: nothing has shipped, so a change updates this document and the tests.

## Plugin identity

- Plugin name `advancedbanksearch`. `prettyui`, `bankcore`, `runeql`, and `gepl` are required dependency aliases. The local manifest maps `bankcore` and `runeql` to their local identifiers and `gepl` to the installed `geprices` directory; PrettyUI retains its mod.io ID. There are no optional dependencies.
- The entry returns nothing. The running session is `_G.__advancedbanksearch_session`; a new load shuts it down first.
- Event names start with `advancedbanksearch_`: `advancedbanksearch_price_wait` (subscribed only while a price wait runs), `advancedbanksearch_search_wait` (while typed text waits to search), `advancedbanksearch_menu` (`MiniMenuReady` and `MiniMenuOpened`, while connected to Bank Core), and `advancedbanksearch_menu_action` (a chosen menu entry, until the next logic tick).
- Saved data: `advancedbanksearch:queries:v1:manifest` and `advancedbanksearch:queries:v1:<a|b>:<n>` chunks of JSON `{ schemaVersion = 1, nextId, queries = { { id, name, query, builder?, icon? } }, nextFolderId, folders = { { id, name, collapsed, icon?, queries = { queryID, ... } } }, order = { { kind = "query" | "folder", id } } }`. `order` is the top level: folders and the queries in no folder; a folder's `queries` are its members in order. A save without `folders` and `order`, as earlier builds wrote, loads with every query ungrouped in `queries` order. On load a query listed by two folders stays in the first, IDs that name nothing and folders without a valid ID or name are dropped (their queries kept), and anything `order` misses goes at its end. Query and folder IDs never change and are never reused. Nothing else is read or written.
- `builder` is optional: the visual conditions a query was built from, `{ match = "all" | "any", rules = { { field, operator, value?, min?, max?, negate? } | { match, rules } } }` with 1 to 6 conditions total, up to 6 groups and 3 nested group levels. `negate = true` excludes that condition while requiring a known field value; boolean exclusions invert explicit true/false. Groups are parenthesized when generating RuneQL. `field` is `name` (`operator` `phrase` or `words`, `value` text) or `qty`, `price`, `gehigh`, or `gelow` (`operator` `equals`, `atleast`, or `atmost` with an integer `value`, or `between` with integer `min` and `max`). `query` stays what is searched. A `builder` is kept on load and save only when it is valid and builds exactly `query`; otherwise it is dropped and the query kept. A record without one loads and saves unchanged.

## What it uses from Bank Core

Only the public extension API in Bank Core's `docs/API.md`, including native bank state discovery:

- `Register{ id = "advancedbanksearch", name = "Advanced Bank Search", icon = "SEARCH", column, onClose, onBankItems, onBankClose, onBankStateChanged }` on the injected `bankcore` or `__bankcore_api`, when the plugin starts and whenever the host reports `bankcore` enabled; `Dispose` when it is reported disabled and when the plugin stops. Registering again replaces the earlier registration.
- The column (`mount`, `resize`, `unmount`) is the plugin's own: a full-width PrettyUI text field, draggable query/folder list, and footer buttons, with an eight-unit gap below the search field, built in `ctx.parent` at `ctx.width` by `ctx.height`, with tooltips in `ctx.overlay`. `resize` with the same width moves the footer and list in place, so the field keeps its focus and typed text; a new width builds the column again. Row dragging reorders sibling entries; it does not accept bank item drops or change folder membership.
- Menus over the column's rows are the plugin's own, from its `MiniMenuReady` handler: a menu `GetMenuItem` describes is a bank item's and is left alone; otherwise the row under the pointer is found from `ctx.parent`'s position, `ctx.width` and `ctx.height`, and the list's scroll. Row actions use Bank Tags’ AddTop menu ordering, with Select (or folder Expand/Collapse) first. A choice is accepted once only after MiniMenuOpened, with the same mounted tree and row-press count. Native item menus remain untouched. Folder submenus use PrettyUI.MiniMenu when available; older PrettyUI builds use the folder chooser. A chosen entry runs on the next logic tick, only while the extension and mounted column are the same and the row's query or folder still exists, both when chosen and when it runs.
- New and Edit register `advancedbanksearch.editor` without an icon and draw a `customView` in the bank item area. The editor uses `view.parent`, `view.overlay`, `view.width` and `view.height`, returning the viewport height and managing its own inner scroll. Name, query, conditions, mode, picker and validation state live in Lua data so redraws never read destroyed inputs. Save and Cancel dispose the editor view and restore any previously open search results. Leaving the view, closing the bank, dependency unload and shutdown release its controls, tooltip contexts and registration.
- The free search page is `{ title = "Search", rows = { { slots = ranked } } }`; a saved query's is `{ title = <name>, rows = ... }`. `ranked` lists each matching stack's object ID in rank order, so an object appears once per matching stack and Bank Core shows its stocked stacks first, then placeholders. A page with no stacks is one label row: "No items match", "RuneQL could not read this search", "This search needs GE Prices", "Waiting for GE prices...", "GE prices did not load", "This search needs RuneQL", or "The bank's items are not available yet".
- Searching or choosing a query calls `SetPage`, then `Open`, which starts at the top. A refusal from `Open` is retained in the app status; the fixed blank gap beneath the search input never displays status text. Choosing the shown query again, clearing the text, deleting the shown query, or RuneQL unloading calls `Close`. Which page shows is the plugin's record of the last page it set plus `IsOpen()`.
- `onBankItems` updates the bank snapshot but keeps a resolved page's membership and slot order fixed, including an empty result. Core updates quantities and shows withdrawn items as zero-quantity pictures in their existing slots. Unresolved pages retry when bank items become readable. Reopening a query or searching again rebuilds results. A price arrival, a GE Prices change, or saving the shown query also ranks the last page again via `SetPage`; these never open it over another plugin. Only a shown page updates the status line or starts a price wait.
- `onClose` ends a price wait and refreshes the column. `onBankClose` drops the last bank read and typed text waiting to search, and closes the editor and folder dialog.
- `GetBankState()` is read after registration and before opening results. `onBankStateChanged(state)` follows `bankOpen`, `viewAll`, `presetOpen`, `searchActive`, and `filterActive`. A restriction silently closes this extension's page, retires its page ID, and ends pending search and price waits, including when Core has already hidden the page. Only an attempted opening reports the restriction; clearing it clears that error without reopening results. Saved queries and other extensions' pages are untouched.
- `GetBankItems` gives `{ objectID, quantity }` per stack; the last read is kept while it answers `busy` or `not_all_items`. `quantity == 0` is a placeholder, left out of saved-query pages.
- Warnings use Bank Tags' click-through overlay banner over the bank title (80-unit horizontal inset, y=5, height=26, centered shadowed red text on the row background). Warning changes update the existing text immediately. Clearing or changing a native restriction hides its warning without reopening results; another opening attempt is needed to warn about the new restriction. Normal match-count status never appears in this banner or beneath Search. The banner belongs to the mounted sidebar and is destroyed on unmount.

## Ranking

- RuneQL's `Compile(text)` gives a plan, or nil and a reason. Each stack is scored with `plan:Score({ name, configName, quantity, fields })`, the name from `config.Obj.FromID(id).name` and the config name from its `configName`. Matches are sorted by score, descending, ties in View All order.
- When `plan:Requirements()` names `price`, `gehigh`, or `gelow`, the plan is ranked only once GE Prices' `isReady()` is true, with `fields.gehigh`, `fields.gelow`, and `fields.price` from `getPrice(id)` (positive numbers only; an error is no price). RuneQL lets a negated range match a row without the field, so ranking before prices load would be wrong.
- RuneQL is read from the injected `runeql` or `__runeql_api`, and GE Prices from `gepl` or `__geprices_api`, only while the host last reported them loaded.

## Visual queries

The editor builds RuneQL text from conditions and saves it through the same `Compile` check as typed text; RuneQL never reads the conditions. A condition becomes one clause: `name:"text"` for a phrase, `(name:"a" AND name:"b")` for all of several words, and `field:[low TO high]` for numbers, with `*` for an open end and both ends included. Clauses are joined with ` AND ` or ` OR `, never mixed, so Lucene's mixed-operator rules never apply. Inside the quotes, `\` and `"` are escaped with `\`; everything else is literal phrase text, which RuneQL splits into lowercase letter-and-digit words. Text with no letter or digit, which RuneQL could never match, is refused. Number conditions are ranges, which match no row missing the field, and they need prices as any other price query does.

Visual gets field descriptors from RuneQL's `Catalog.Fields()` when the dependency loads or reloads. The default field menu is limited to name, qty, price, category, skills, types, combatStyle, slot, tier, tradeable, and augmented; trusted saved conditions also retain their existing fields. Query compilation continues to support all discovered fields. It loads metadata keeping only the name, quantity, and GE price fields defined locally. Canonical keys, labels, types, and list metadata come from RuneQL. Selecting or editing a catalog text field calls `Catalog.Values(fieldKey, { query = text })`. A reusable four-column grid shows up to 24 labels at a time, with previous/next buttons for larger lists; choosing one fills its canonical value and collapses the grid. Clearing the field opens choices again. Selected values stay collapsed even if the client echoes their content-change event. There is no item scan or persistent value cache. Field and comparison menus use native ComboBox controls with labels and IDs in matching alphabetical order; they do not use PrettyUI ordered dropdown lists. The clear icon is a sibling layer positioned over the input, since native input fields cannot parent child components. Cancel, Save, and validation feedback stay in a bottom-anchored footer; only the editor body scrolls in a separate SimpleView. Editor construction cleans up its window if any control fails, callbacks are ignored until construction completes and after destruction, and closing destroys all owned controls as well as the window. Dependency changes close the editor so it never keeps calling a stale catalog API. Unknown saved field conditions are retained while RuneQL is unavailable, but are used in Visual only after they regenerate the exact saved query with the current metadata.

New catalog text conditions use exact whole-value comparisons: `field:["value" TO "value"]`. Scalar text has equals/not_equals; lists have includes/excludes. Negatives generate `(field:[* TO *] AND NOT field:["value" TO "value"])`, so missing values and empty lists never match. Existing phrase/words conditions still regenerate the original query, but open in Advanced; those old operators are not offered for new catalog conditions. Boolean conditions generate `field:true` or `field:false`, preserving unknown values as unknown rather than treating a missing value as false. Tier, dose, and base value use inclusive numeric ranges. Runtime scoring supplies `configName`, so RuneQL resolves attributes without copying the catalog or searching by display name. Only price, gehigh, and gelow require GE Prices.

## Host behavior it relies on

Checked with Bank Core's stand-in host only: injected `PluginDependencyUpdate` failures for required dependency recovery; `PersistentDB:GetString` and `SetString` per plugin; PrettyUI's `TextField` (with `SetDisabled` and `SetPlaceholder`), `ComboBox` (`SetEntries`, `Select`, `GetSelectedID`, with whole-number entry IDs and an `order` on every entry, so PrettyUI builds its ordered combo box), `Text`, `List` (with `_onEntryClick`, `rows`, and `scrollY`), `SpriteButton` (`ARROW_UP`, `ARROW_DOWN`), `Sprites.SPRITE_BUTTONS.SWAP`, `Tooltip` (`bind`, `set`, `unbind`, `registerContext`, `unregisterContext`), a `ui.Button` in the `BUTTON_PANEL` style (318 when `id.StyleSheet` does not name it) answering `ONBUTTONPRESSED`, with a `ui.Sprite` icon beside it, `SimpleButton` (with `SetDisabled` and `SetActive`), and `Window`; `ui.Rectangle` and a rotated `ui.Sprite` (`id.Sprite.BANK_ARROW_UP_0`) in list rows; `ui.Interfaces:GetComponent(id.Component.TOPLEVEL_V2__BANK_LAYER)` for the editor's and folder dialog's parent; `Mouse.GetPosition` and `game.options.InterfaceScale`; `MiniMenu` `entries`, `entryCount`, `Add`, and `Swap`, and `MiniMenuActionType.CANCEL`; `Event.Logic` and `Event.MiniMenuReady`. The manifest sets `hasRibbonIcon` to `false`, and the plugin does not subscribe to `Event.ContentLayerReady`.

## Plugin Hub settings

`hasSettingsIcon: true` enables the settings cog. The plugin subscribes to `Event.SettingsLayerReady` under `advancedbanksearch_settings`, mounts a PrettyUI SimpleView in the supplied `component`, destroys the previous mount on each event, and unsubscribes/destroys on shutdown. No ContentLayerReady subscription or ribbon icon is used for settings. Preferences are saved separately from queries under `advancedbanksearch:settings:v1`; failed writes do not change active behavior. The settings are new-editor mode, quick-search placeholder inclusion, and search debounce (5, 10, or 20 logic ticks).

## Shared Bank Tags interaction patterns

The query tree, row drag gestures, geometry calibration, name/icon editor and 8-by-5 icon picker are ported from the Bank Tags checkout into plugin-owned modules. Bank Tags is not a runtime dependency. Only item selection and saved-query-specific callbacks differ. Icons are optional strings containing a stable config name or #objectID, matching Bank Tags references. Unknown icon references draw no icon and never discard a query. A rejected metadata write leaves the name, icon, conditions, folder and order unchanged.

## Query import and share

The native footer matches Bank Tags: EXPORT icon, New Query, and a PENCIL icon shown for an existing selected query. Deletion remains in the row menu. Share opens the copied Import/Share tabbed window.

Query share codes use `format = "advancedbanksearch-queries"`, `version = 1`, ordered `queries` and `folders` arrays, and `order` entries `{kind, name}`. Query records contain name, RuneQL, optional visual builder, optional icon reference and optional folder name. Folder records contain name, icon and collapse state. Numeric local IDs never leave the save. The decoder bounds envelope size/counts and visual tree depth, validates names, numeric icon references and folder links, and compiles every expression through RuneQL. Wrong-format or invalid codes cannot become a ready preview.

The import window has the same single-record name/icon/folder customization and explicit-save flow as Bank Tags. Case-insensitive query name matches replace content under the existing ID; new queries/folders get fresh IDs. Existing folder settings and unrelated data are kept. The whole import uses one Commit; a failed write cannot change live data or the published save. Oversized code fields display a size reason. Backups retain metadata and order. Bank Tags layout codes are not accepted as queries.
